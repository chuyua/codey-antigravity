# NexusDock 独立咨询与处理记录

2026-10-09 经 NexusDock Windows 节点的命令接口调用现有 agy-worker，只读咨询宿主解耦、流错误和 CI 产物验收。调用退出码为 0，返回一份 `status=SUCCESS`、无 error 且 response 非空的 JSON。只提供公开仓库、协议和测试计划，未提供账号文件或凭据。Claude 接口先返回未登录，最终意见来自 agy。

## 采纳并验证的建议

- 默认描述必须符合宿主严格解析字段；新建第三方线路三项能力的缺省值均为 false。已有线路通过宿主的既有设置关闭，并在真实安装后核验。
- 已产生内容或工具调用后不自动重放请求。无 finishReason、裸 JSON error 或晚到 error 以失败终态结束，并覆盖单一终态与无重复执行测试。
- 验收 CI 的实际 DLL/代理，不把源码单测等同于发行包测试。包括 ABI 导出/内存释放、Unicode 与空格路径、安装/启动/停止/端口和 PID 身份、包篡改与凭据排除。
- 检查 Windows 运行时依赖，MSVC 发行构建静态链接 CRT；macOS 与 Linux 在对应 CI runner 验证。

## 经核查调整的建议

咨询提到代理强制覆盖宿主开关，但没有这样的跨进程宿主配置契约；对外部线路配置硬编码标志不能保证宿主不发送 WS/compact。默认描述保持兼容，已有线路用宿主设置关闭。

咨询提到静态窗口回退表。目录没有可靠窗口时本项目继续不声明窗口，不使用猜测值；旧宿主无法下发窗口的限制明确写在文档中。

咨询使用了通用 `finish_reason=error` 表述；Codey Responses 实际应使用 `response.failed` 终态。具体协议以宿主与代理测试为准。咨询意见不代替 CI 结果和真实宿主/OAuth 验证。
